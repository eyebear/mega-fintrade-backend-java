# Quant CSV Input Contract

This document describes the CSV input files consumed by `mega-fintrade-backend-java`.

These files are expected to be produced by the Python quantitative engine:

    mega-fintrade-quant-engine

The Java backend imports these files from:

    data/input

Expected files:

    data/input/risk_metrics.csv
    data/input/backtest_results.csv
    data/input/strategy_signals.csv
    data/input/portfolio_equity_curve.csv

---

## General Rules

All CSV files must follow these rules:

- The first row must be the header row.
- Header names must match the expected format exactly.
- Column order matters.
- Empty required fields are rejected.
- Invalid decimal values are rejected.
- Invalid date values are rejected.
- Rows with incorrect column counts are rejected.
- Rejected records are stored in the `import_rejection` table.
- Import run history is stored in the `import_audit` table.

The backend currently uses strict CSV validation. If a file header or row format is invalid, the import may fail fast.

## File 1 — risk_metrics.csv

### Path

    data/input/risk_metrics.csv

### Purpose

Stores risk and performance metrics generated by the quant engine.

Examples include:

- Volatility
- CAGR
- Sharpe ratio
- Max drawdown

### Expected Header

    scope,symbol,metric,value

### Column Definitions

| Column | Type | Required | Description |
|---|---|---|---|
| `scope` | text | yes | Metric scope, such as `symbol` or `portfolio` |
| `symbol` | text | yes | Ticker symbol or `ALL` for portfolio-level metrics |
| `metric` | text | yes | Metric name |
| `value` | decimal | yes | Metric value |

### Example

    scope,symbol,metric,value
    symbol,AAPL,volatility,0.0335
    portfolio,ALL,cagr,0.8500
    portfolio,ALL,sharpe_ratio,1.2500
    portfolio,ALL,max_drawdown,-0.1800

### Notes

Portfolio-level metrics should use:

    scope = portfolio
    symbol = ALL

The report summary service uses portfolio-level metrics such as:

    sharpe_ratio
    max_drawdown

## File 2 — backtest_results.csv

### Path

    data/input/backtest_results.csv

### Purpose

Stores daily backtest result rows from the quant engine.

### Expected Header

    date,portfolio_return,benchmark_return,turnover,portfolio_wealth,benchmark_wealth

### Column Definitions

| Column | Type | Required | Description |
|---|---|---|---|
| `date` | date | yes | Trading date in `YYYY-MM-DD` format |
| `portfolio_return` | decimal | yes | Daily portfolio return |
| `benchmark_return` | decimal | yes | Daily benchmark return |
| `turnover` | decimal | yes | Daily portfolio turnover |
| `portfolio_wealth` | decimal | yes | Portfolio wealth index |
| `benchmark_wealth` | decimal | yes | Benchmark wealth index |

### Example

    date,portfolio_return,benchmark_return,turnover,portfolio_wealth,benchmark_wealth
    2026-01-02,0.0100,0.0080,0.1200,1.0100,1.0080
    2026-01-03,-0.0050,-0.0040,0.1000,1.0049,1.0040

## File 3 — strategy_signals.csv

### Path

    data/input/strategy_signals.csv

### Purpose

Stores strategy signal output from the quant engine.

The current project scope uses a fixed configured symbol universe.

Current symbols:

    AAPL
    MSFT
    GOOGL
    SPY

The backend currently supports this configured wide-format CSV structure. Dynamic symbol support is intentionally left for a future version.

### Expected Header

    date,aapl_close,aapl_sma_short,aapl_sma_long,aapl_signal,msft_close,msft_sma_short,msft_sma_long,msft_signal,googl_close,googl_sma_short,googl_sma_long,googl_signal,spy_close,spy_sma_short,spy_sma_long,spy_signal

### Column Definitions

| Column | Type | Required | Description |
|---|---|---|---|
| `date` | date | yes | Trading date in `YYYY-MM-DD` format |
| `aapl_close` | decimal | yes | AAPL close price |
| `aapl_sma_short` | decimal | yes | AAPL short moving average |
| `aapl_sma_long` | decimal | yes | AAPL long moving average |
| `aapl_signal` | decimal | yes | AAPL strategy signal |
| `msft_close` | decimal | yes | MSFT close price |
| `msft_sma_short` | decimal | yes | MSFT short moving average |
| `msft_sma_long` | decimal | yes | MSFT long moving average |
| `msft_signal` | decimal | yes | MSFT strategy signal |
| `googl_close` | decimal | yes | GOOGL close price |
| `googl_sma_short` | decimal | yes | GOOGL short moving average |
| `googl_sma_long` | decimal | yes | GOOGL long moving average |
| `googl_signal` | decimal | yes | GOOGL strategy signal |
| `spy_close` | decimal | yes | SPY close price |
| `spy_sma_short` | decimal | yes | SPY short moving average |
| `spy_sma_long` | decimal | yes | SPY long moving average |
| `spy_signal` | decimal | yes | SPY strategy signal |

### Example

    date,aapl_close,aapl_sma_short,aapl_sma_long,aapl_signal,msft_close,msft_sma_short,msft_sma_long,msft_signal,googl_close,googl_sma_short,googl_sma_long,googl_signal,spy_close,spy_sma_short,spy_sma_long,spy_signal

A future version should normalize strategy signals into this structure:

    date,symbol,close,short_ma,long_ma,signal

Example future format:

    date,symbol,close,short_ma,long_ma,signal
    2026-01-02,AAPL,190.00,188.00,185.00,1.0
    2026-01-02,MSFT,410.00,408.00,405.00,1.0
    2026-01-02,GOOGL,140.00,138.00,135.00,1.0
    2026-01-02,SPY,500.00,498.00,495.00,1.0

That future design would allow the platform to support any number of symbols without changing Java entity or importer code.

## Import Behavior

The main direct import endpoint is:

    POST /api/import/all

This imports all four default CSV files.

The Spring Batch import endpoint is:

    POST /api/batch/run

The scheduled quant import job also imports the same default files.

---

## Audit Logging

Every scheduled import run creates an audit record.

Audit records include:

- Job name
- Status
- Start time
- Completion time
- Imported row counts
- Error message if failed

Audit endpoint:

    GET /api/import/audit

---

## Rejection Logging

Rejected CSV records are stored when validation fails.

A rejection record includes:

- File name
- Line number
- Raw record
- Rejection reason
- Created time

Rejection endpoint:

    GET /api/import/rejections

---

## Common CSV Errors

### Missing File

Example reason:

    CSV file not found: data/input/risk_metrics.csv

### Invalid Header

Example reason:

    Invalid CSV header

This usually means the CSV header does not exactly match the expected header.

### Invalid Column Count

Example reason:

    Invalid column count. Expected: 4, actual: 2

This means the row does not contain the required number of columns.

### Invalid Date

Example reason:

    Invalid date field

Dates must use:

    YYYY-MM-DD

Example:

    2026-01-02

### Invalid Decimal

Example reason:

    Invalid decimal field

Decimal fields must contain valid numeric values.

Valid examples:

    0.0100
    -0.1800
    1.2500

Invalid examples:

    NOT_A_NUMBER
    abc
    empty field
