# Quant Output CSV Schemas

This document defines the CSV input files that the Java backend expects from the Python quant engine.

Project 1:

- Repository: mega-fintrade-backend-java
- Role: Java Spring Boot backend
- Input folder: data/input

Project 2:

- Repository: mega-fintrade-quant-engine
- Role: Python quantitative backtesting and analytics engine
- Output folder: data/output

The Java backend expects the following files to be copied from Project 2 into Project 1:

- data/input/risk_metrics.csv
- data/input/backtest_results.csv
- data/input/strategy_signals.csv
- data/input/portfolio_equity_curve.csv

These schemas must match the actual CSV files generated by the Python quant engine.

---

# 1. risk_metrics.csv

Expected file path:

    data/input/risk_metrics.csv

Purpose:

    Stores portfolio-level and asset-level risk metrics generated by the Python quant engine.

Expected columns:

| Column | Type | Required | Description |
|---|---|---|---|
| scope | String | Yes | Metric level. Expected values include portfolio or asset. |
| symbol | String | Yes | Ticker symbol. Use ALL for portfolio-level metrics. |
| metric | String | Yes | Metric name, such as cagr, sharpe_ratio, or max_drawdown. |
| value | Decimal | Yes | Numeric metric value. |

Expected header:

    scope,symbol,metric,value

Example rows:

    portfolio,ALL,cumulative_return,0.0335
    portfolio,ALL,cagr,0.8500
    portfolio,ALL,annualized_volatility,0.1850
    portfolio,ALL,sharpe_ratio,1.2450
    portfolio,ALL,max_drawdown,-0.0120
    portfolio,ALL,hit_rate,0.6667
    asset,AAPL,cumulative_return,0.0210
    asset,AAPL,cagr,0.5200
    asset,AAPL,annualized_volatility,0.2420
    asset,AAPL,sharpe_ratio,0.9700

Notes:

- scope identifies whether the metric belongs to the whole portfolio or to an individual asset.
- symbol should be ALL when scope is portfolio.
- value should be stored as a decimal number in the Java backend.

# 2. backtest_results.csv

Expected file path:

    data/input/backtest_results.csv

Purpose:

    Stores time-series backtest performance results.

Expected columns:

| Column | Type | Required | Description |
|---|---|---|---|
| date | Date | Yes | Trading date in YYYY-MM-DD format. |
| portfolio_return | Decimal | Yes | Portfolio return for the date. |
| benchmark_return | Decimal | Yes | Benchmark return for the date. |
| turnover | Decimal | Yes | Portfolio turnover for the date. |
| portfolio_wealth | Decimal | Yes | Portfolio wealth index value. |
| benchmark_wealth | Decimal | Yes | Benchmark wealth index value. |

Expected header:

    date,portfolio_return,benchmark_return,turnover,portfolio_wealth,benchmark_wealth

Example rows:

    2024-01-02,0.0000,0.0000,1.0000,1.0000,1.0000
    2024-01-03,-0.0042,-0.0028,0.0000,0.9958,0.9972
    2024-01-04,-0.0079,-0.0054,0.0000,0.9879,0.9918
    2024-01-05,0.0025,0.0018,0.5000,0.9904,0.9936

Notes:

- portfolio_wealth and benchmark_wealth are index-style values.
- A value of 1.0000 means the starting wealth level.
- Values above 1.0000 mean growth from the starting point.
- Values below 1.0000 mean decline from the starting point.

# 3. strategy_signals.csv

Expected file path:

    data/input/strategy_signals.csv

Purpose:

    Stores strategy signal output generated by the Python quant engine.

| AAPL_short_ma | Decimal | Yes | AAPL short moving average. |
| AAPL_long_ma | Decimal | Yes | AAPL long moving average. |
| AAPL_signal | Decimal | Yes | AAPL strategy signal. |
| MSFT_close | Decimal | Yes | MSFT closing price. |
| MSFT_short_ma | Decimal | Yes | MSFT short moving average. |
| MSFT_long_ma | Decimal | Yes | MSFT long moving average. |
| MSFT_signal | Decimal | Yes | MSFT strategy signal. |
| GOOGL_close | Decimal | Yes | GOOGL closing price. |
| GOOGL_short_ma | Decimal | Yes | GOOGL short moving average. |
| GOOGL_long_ma | Decimal | Yes | GOOGL long moving average. |
| GOOGL_signal | Decimal | Yes | GOOGL strategy signal. |
| SPY_close | Decimal | Yes | SPY closing price. |
| SPY_short_ma | Decimal | Yes | SPY short moving average. |
| SPY_long_ma | Decimal | Yes | SPY long moving average. |
| SPY_signal | Decimal | Yes | SPY strategy signal. |

Expected header:

    date,AAPL_close,AAPL_short_ma,AAPL_long_ma,AAPL_signal,MSFT_close,MSFT_short_ma,MSFT_long_ma,MSFT_signal,GOOGL_close,GOOGL_short_ma,GOOGL_long_ma,GOOGL_signal,SPY_close,SPY_short_ma,SPY_long_ma,SPY_signal

Example rows:

    2024-01-02,185.64,184.20,182.75,1.0,370.87,368.10,365.90,1.0,138.17,137.20,136.10,1.0,472.65,470.30,468.90,1.0
    2024-01-03,184.25,184.35,182.91,1.0,370.60,368.75,366.40,1.0,138.92,137.45,136.35,1.0,471.43,470.55,469.10,1.0
    2024-01-04,181.91,184.10,183.05,1.0,367.94,368.95,366.85,1.0,136.39,137.30,136.55,1.0,468.30,470.40,469.35,1.0

Notes:

- This file uses a wide format.
- Each symbol has its own group of columns.
- Signal values are numeric.
- A signal value of 1.0 means the strategy is active or invested.
- A signal value of 0.0 means the strategy is inactive or not invested.

# 4. portfolio_equity_curve.csv

Expected file path:

    data/input/portfolio_equity_curve.csv

Purpose:

    Stores portfolio and benchmark wealth curves over time.

Expected columns:

| Column | Type | Required | Description |
|---|---|---|---|
| date | Date | Yes | Trading date in YYYY-MM-DD format. |
| portfolio_wealth | Decimal | Yes | Portfolio wealth index value. |
| benchmark_wealth | Decimal | Yes | Benchmark wealth index value. |

Expected header:

    date,portfolio_wealth,benchmark_wealth

Example rows:

    2024-01-02,1.0000,1.0000
    2024-01-03,0.9958,0.9972
    2024-01-04,0.9879,0.9918
    2024-01-05,0.9904,0.9936
    2024-01-08,1.0112,1.0074

Notes:

- This file is a simplified equity curve.
- It is useful for charting portfolio performance against the benchmark.
- It will later map to the PortfolioEquityPoint entity in the Java backend.

# Data Flow Summary

The intended data flow is:

    Project 2 generates raw market data.
    Project 3 cleans market data and calculates daily returns.
    Project 2 consumes Project 3 outputs and generates quant analytics files.
    Project 1 receives Project 2 output files under data/input.

Full flow:

    mega-fintrade-quant-engine
      data/raw/raw_market_data.csv

    mega-fintrade-market-engine-cpp
      data/input/raw_market_data.csv
      data/output/cleaned_market_data.csv
      data/output/daily_returns.csv

    mega-fintrade-quant-engine
      data/processed/cleaned_market_data.csv
      data/processed/daily_returns.csv
      data/output/risk_metrics.csv
      data/output/backtest_results.csv
      data/output/strategy_signals.csv
      data/output/portfolio_equity_curve.csv

    mega-fintrade-backend-java
      data/input/risk_metrics.csv
      data/input/backtest_results.csv
      data/input/strategy_signals.csv
      data/input/portfolio_equity_curve.csv

# Validation Rules for Future Import Services

The Java backend import services should validate:

1. File exists.
2. File is not empty.
3. Header matches the expected schema.
4. Required columns are present.
5. Date fields use YYYY-MM-DD format.
6. Numeric fields can be parsed as decimals.
7. Duplicate rows are handled safely.
8. Invalid rows are either rejected or logged.

Future import services should not silently accept malformed files.
